# WizFile - A Name on a Disk You Can Open

## Brought for

A filename you half remember.
A folder that should contain an installer you saved last month.
A size sort when a disk is suddenly full and you need the largest files you created.
Not a hunt through another person's profile.

## Already true

The disk is one you are allowed to read.
You can open Explorer on the same letter and see the same tree.
You are looking for a name or a size, not for the contents of every document.
A backup drive plugged in is optional. The system disk is enough for a first try.

## The sheet

- [ ] One drive letter selected
- [ ] The query is a fragment you remember, not the whole path
- [ ] Results are names you recognize
- [ ] A huge file is opened or identified before anything is deleted
- [ ] System folders are not the thing you came to erase
- [ ] The search closes when the file is found

## Clock

08:00 Select the drive that filled up.
08:01 Type three letters from the filename.
08:02 Sort by size only if the name did not appear.
08:04 Open the parent folder from the result.
08:06 Decide there, in Explorer, whether the file stays.

## A reading that lies

A result on the wrong letter is a different disk.
A path under Windows is not a download you should delete from this list.
Two files with the same name in different folders are not duplicates until you open them.
A size of zero is an empty file, not a hidden copy of your project.
The index can lag a file you just saved. Save, then search again.

## One setting you pin

Remember the last drive only if you always search that drive.
Jumping to the folder is the action you want. Deleting from the result list is the action you avoid on day one.
Highlighting the match in the name is enough. Extra columns can wait.
If the window starts on the wrong disk, fix that before you build a habit.

## Questions from the other chair

Where did you search. Which letter.
What fragment you typed.
Whether the file opened.
Whether you deleted anything. The answer should be no on a first look.
Which folder you will clean later, by hand, if the disk is still full.

## Put it back

Clear the query.
Leave the drive selection on the disk you actually use.
Do not leave a delete pending.
The tool can stay installed. The search does not need to be running.

## Tomorrow

You still know the fragment that worked.
The large file, if you kept it, has a folder you can explain.
A full disk after a successful search means the space is elsewhere. Look at the next largest name, still without deleting from the list.
Uninstall is the undo. The index is the disk's, not a private database you must purge.

## Not the same job

A duplicate matcher judges pairs. This only finds names.
A space map draws folders. This sorts files.
A cleaner removes caches you did not name. Here you name the file first.
Content search inside documents is a different index.
Someone else's PC is out of scope.
